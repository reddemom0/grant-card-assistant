## 8. Thinking-tag handling (prompt hygiene)

**❌ Conflict — both happening:**

- **Prompt instructs `<thinking>` inline.** `etg-writer.md:491` ("Always use your `<thinking>` section to determine where you are in the workflow"), `:559` ("ALWAYS use `<thinking>` tags before responding"), `:561` ("If your `<thinking>` shows something is COMPLETE, do not repeat it"), `:563` ("Your `<thinking>` is for your internal reasoning"). Beta header `interleaved-thinking-2025-05-14` is set (`client.js:534`). The trace shows BOTH:
- Real `thinking` content blocks at trace lines 15-25, 233-239, 271-276, 365-373 (these are extended-thinking outputs — type `thinking`, not `text`).
- Inline `<thinking>...</thinking>` text within `text` content blocks at lines 41-50, 67-78, 93-105, 120-126, 144-146, 166-170, 255-265, 345-353. These are the agent following the prompt instruction to literally write `<thinking>` tags into text output, AS WELL AS the API-level extended thinking.

**⚠️ Why both:** the prompt was likely written before extended-thinking-as-API-feature was widely available; the convention of inline `<thinking>` tags is a manual workflow-tracking pattern. Now that interleaved thinking is enabled at the API, the inline pattern is redundant AND leaks into user-visible text content (the frontend renders `text` blocks; users see the literal tags).

## A. Top 5 fixes (ranked by impact)

1. **Add fabrication-prevention rules to the ETG prompt** (highest impact, addresses the most damaging issue). Mirror `DEAL_CREATION.md` Section 0.2 and 5.4.1 inside `etg-writer.md`. Specifically forbid: ROI percentages, hourly rates, commission rates, gross margins, ARR, account counts unless explicitly user-provided. Require any retained number to be either (a) from user, (b) from the HubSpot deal, (c) from a fetched/cited URL. Mark estimates with a visible flag. This single change would have prevented all of: 1,320% ROI, $32 hourly, $500-750k ARR, 60% margin, 20% commission, 25-30 accounts.

2. **Resolve the `<thinking>` tag conflict.** Either disable inline `<thinking>` instruction (since extended thinking is enabled at API level — preferred) OR disable extended thinking for this agent. The current dual setup leaks tags into user-visible text. Lowest-cost fix: remove the four prompt instructions at `etg-writer.md:491, 559, 561, 563` that instruct the model to write `<thinking>` tags inline.

3. **Add a contact-trainee mismatch protocol.** When `get_hubspot_contact` returns a contact whose name/email differs from the user-provided trainee, instruct: (a) search by trainee email via `search_hubspot_contacts`, (b) if not found, offer to create via `create_hubspot_contact` and `associate_contact_with_company`, (c) do not silently proceed with the wrong contact in business case content. The tools are already in the loadout; only the prompt needs updating.

4. **Add the BC ETG prioritization framework.** Insert a new prompt section listing the six priority factors (first-time, small business, skills-shortage region, BC public post-secondary trainer, trades apprenticeship 3/4, priority sectors / Look West list). Either inline in `etg-writer.md` or as a loadable skill (would also require adding `LOAD_SKILL_TOOL` to `etg-writer`'s case in `definitions.js:2076-2079`).

5. **Strengthen the state-check rule.** Move the state-check from `<workflow_tracking>` (currently an internal protocol) into the FIRST instruction the agent reads after the role definition. Or add an explicit rule: "If the user's message is ambiguous about whether work is new or revising existing work, run `memory_recall` and check the last 10 conversation turns BEFORE drafting anything new." This addresses the redo-Q4 bug.

**Secondary cleanup (not in top 5):** purge dead tool names from prompt (`getProjectEmailHistory` etc.); align frontmatter casing with runtime snake_case; remove vestigial HubSpot write tools (`create_hubspot_company`, `update_hubspot_company`, `associate_contact_with_company`, `search_getgranted`) from ETG's loadout if not needed; resolve orphan `</output>` tag at `etg-writer.md:565`.
