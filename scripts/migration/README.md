# scripts/migration

Scripts for moving staff My Drive files into the Granted Files and Granted Archive shared drives, and for keeping the "Drive migration log" sheet.

**No data lives here.** Drive IDs, account addresses, member lists, run labels and the approver are read from `dist/migration/config.json`. Plans, ledgers, snapshots and reports are read from and written to `dist/inventory/`. Both are gitignored. Credentials come from the service-account key in `.env` (domain-wide delegation).

| Script | What it does | Writes to Drive? |
|---|---|---|
| `migration-log.mjs` | Shared helpers: loads the config, auth tokens, CSV/JSONL loading, Sheets calls, turns ledger lines into log rows, appends a finished run to the sheet. | Only the log sheet (append) |
| `build-v6.mjs` | Builds the move plan from v5 + the sharing snapshot: target drive and path per file, sharing actions (restore / remove / lapse), client-owned shortcuts, Google Meet rule, destination fixes, notice data, summary. | No (local files only) |
| `dryrun.mjs <owner>@` | Read-only dry run for one owner: re-checks each file, resolves destination folders, lists folders to create and sharing actions. Writes `dist/inventory/dryrun-<owner>.md`. | No (read-only scope) |
| `move-owner.mjs <owner>@` | Live move for one owner: creates missing folders, moves each file as its owner, verifies by ID, applies the planned sharing actions, writes a ledger line before every change, writes a report, appends to the log sheet. `--fixup` also applies the fix-up adds. `--undo` reverses the owner's done actions from the ledger. `--plan <csv>` / `--tag <name>` run against a one-off plan with its own ledger (used for tests). | Yes: folders, moves, permission add/remove. Never trash, delete files, rename or copy. |
| `owner-sheet.mjs <owner>@` | Builds "Your moved files – <owner> – <date>" from a run's ledger in the admin account's My Drive: tabs "Moved to Granted Files" / "Moved to Granted Archive", columns File (link) / Was in / Now in, sorted by Now in. Shares it with the owner only, as viewer, no notification email; prints the link. Runs automatically at the end of every live `move-owner.mjs` run (`--no-owner-sheet` to skip). | Creates one sheet + one viewer permission |
| `trash-empty-folders.mjs` | Trashes empty folders (no file anywhere below) in both shared drives. Protects Clients, Programs, Departments and their direct children; folders under 7 days old that the migration didn't create; "Returned from Granted Archive" folders; Archive owner and person folders; and every ancestor of a protected folder. `--dry` (default) walks both drives read-only and writes `empty-folder-cleanup-plan.csv` + `empty-folder-cleanup-dryrun.md`. `--go` trashes the plan deepest first, re-checking each folder live, with a ledger line before every change, then appends to the log sheet. `--undo` restores from the ledger. | `--go`/`--undo` only: trash / untrash folders. Never files, never a permanent delete. |
| `rename-folders.mjs --from "<old>" --to "<new>" --run "<label>" --tag <prefix>` | Renames every Granted Files folder called `<old>` to `<new>`. A folder whose parent already holds `<new>` (ignoring case and spaces) is listed as a merge case instead. Also lists other misspellings of "Accessibility" in folder names. `--dry` (default) walks the drive read-only and writes `<tag>-plan.csv` + `<tag>-dryrun.md`. `--go` renames the plan, re-checking each folder live (name, parent, no correctly named sibling), with a ledger line before every change, then appends to the log sheet. `--undo` renames back from the ledger. Explicit-ID mode: `--list <json> --run … --tag …` renames exactly the listed folders (`[{group, id, parent, path, from, to}]`), never other folders with the same name; `--verify` checks each ID's new name and that no listed old name is left at program level (outputs `<tag>-renames-*`). | `--go`/`--undo` only: folder name changes. IDs, parents and contents stay the same. Never files. |
| `merge-client-folders.mjs [--tag <prefix>] [--run "<label>"]` | Merges duplicate client folders into a keeper (groups from `dist/inventory/<tag>-groups.json`; `--tag` defaults to `client-merge-certain`, and all outputs and the ledger use the same prefix). A group can have several sources: they merge in order, each planned against the keeper as it will look once the earlier ones are in. A source with `only: [<relative paths>]` is partial: just those subtrees move (each into the keeper folder matching its parent), the source root stays, and the dry run lists every file with the reason from `onlyReason`/`cues`. An optional per-group `archName` sets the Archive path (`Merge duplicates/<archName>/…`; default the keeper's name). Level by level: a matching subfolder (ignoring case, spacing, punctuation) is merged into; any other subfolder is moved whole; a same-name + same-md5 file, or a shortcut whose target is already in the keeper, goes to `Granted Archive/Merge duplicates/<Keeper>/<path>`; a same-name file with different content is moved next to the existing one without renaming. Emptied source folders are trashed. Groups with shortcuts are held unless `--include-shortcuts`. `--dry` (default) walks read-only and writes `<tag>-plan.json` + `<tag>-dryrun.md`. `--go` runs the plan one group at a time, re-checking each item live, with a ledger line before every change and verification by ID, then appends to the log sheet; a re-run skips what the ledger has done. `--verify` is a read-only walk that writes `<tag>-after-go.md`. `--undo` untrashes and moves everything back from the ledger. | `--go`/`--undo` only: file and folder moves, folder trash / untrash, folder creates under `Granted Archive/Merge duplicates`. No renames, deletes or sharing changes. |
| `build-log.mjs` | One-off: built the "Drive migration log" sheet and the "Dropbox migration log" file from the existing ledgers. Refuses to run again once the sheet exists (`--check` previews locally without Drive calls). | Creates the two log files |

Typical order for one owner:

1. `node scripts/migration/build-v6.mjs`, after any rule change.
2. `node scripts/migration/dryrun.mjs <owner>@`, then review `dryrun-<owner>.md`.
3. `node --network-family-autoselection-attempt-timeout=5000 scripts/migration/move-owner.mjs <owner>@`, after approval.

How to read the log sheet: `dist/inventory/migration-log-README.md`.
